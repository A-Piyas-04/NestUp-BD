\paragraph{Registration Flow}
\begin{enumerate}
\item Validate required fields (name, email, password)
\item Check email format and password length (min 6 characters)
\item Verify email uniqueness in database
\item Hash password using bcrypt
\item Create user record in database
\item Generate JWT token with 7-day expiration
\item Set HTTP-only cookie with security flags
\item Return user data and token
\end{enumerate}

\paragraph{Login Flow}
\begin{enumerate}
\item Validate email and password presence
\item Find user by email (case-insensitive)
\item Compare provided password with hashed password
\item Generate new JWT token on successful authentication
\item Set secure HTTP-only cookie
\item Return user profile and token
\end{enumerate}

\subsection{Middleware Architecture}
\label{subsec:middleware-architecture}

\textbf{Location}: \folder{server/middleware/}

\subsubsection{Authentication Middleware}
\label{subsubsec:auth-middleware}

\textbf{File}: \file{auth.js}

\textbf{Purpose}: JWT token validation and user authentication for protected routes.

\paragraph{Key Functions}
\begin{itemize}
\item \textbf{verifyToken}: Validates JWT tokens from cookies or Authorization header
\item \textbf{generateToken}: Creates new JWT tokens with configurable expiration
\item \textbf{checkAuth}: Ensures user is authenticated for protected routes
\end{itemize}

\paragraph{Token Validation Process}
\begin{enumerate}
\item Extract token from HTTP-only cookie or Authorization header
\item Verify token signature using JWT\_SECRET from environment
\item Decode user ID from token payload
\item Fetch user details from database (excluding password)
\item Attach user object to request for route handlers
\item Handle token expiration and invalid token errors
\end{enumerate}

\paragraph{Security Features}
\begin{itemize}
\item \textbf{HTTP-Only Cookies}: Prevents XSS attacks on tokens
\item \textbf{Secure Flag}: HTTPS-only cookies in production
\item \textbf{SameSite Policy}: CSRF protection
\item \textbf{Token Expiration}: 7-day automatic expiration
\item \textbf{Environment-based Secrets}: Configurable JWT secrets
\end{itemize}

\subsubsection{File Upload Middleware}
\label{subsubsec:upload-middleware}

\textbf{File}: \file{upload.js}

\textbf{Purpose}: Handles file uploads with validation and storage management.

\paragraph{Configuration}
\begin{itemize}
\item \textbf{Storage Engine}: Disk storage with unique filename generation
\item \textbf{File Size Limit}: 5MB maximum per file
\item \textbf{File Type Filtering}: Images only (MIME type validation)
\item \textbf{Destination}: Uploads directory with automatic creation
\item \textbf{Filename Strategy}: Timestamp + random suffix for uniqueness
\end{itemize}

\paragraph{Upload Process}
\begin{enumerate}
\item Validate file type (images only)
\item Check file size against 5MB limit
\item Generate unique filename with timestamp
\item Store file in uploads directory
\item Return file path for database storage
\item Handle upload errors gracefully
\end{enumerate}

\paragraph{Token Security Features}
\begin{itemize}

\item \textbf{Secure Flag}: Ensures cookies are only sent over HTTPS in production
\item \textbf{SameSite Policy}: Provides CSRF protection by restricting cross-site requests

\paragraph{Password Security}
\begin{itemize}
\item \textbf{bcrypt Hashing}: Industry-standard password hashing with salt
\item \textbf{Minimum Length}: 6-character minimum password requirement
\item \textbf{Hash Comparison}: Secure password verification without plaintext storage
\item \textbf{No Password Exposure}: Passwords excluded from API responses
\end{itemize}

\textbf{Purpose}: Verifies JWT tokens and protects routes from unauthorized access.

\paragraph{Key Features}
\begin{itemize}
\item \textbf{Token Verification}: Validates JWT tokens from HTTP-only cookies
\item \textbf{User Context}: Attaches authenticated user information to request object
\item \textbf{Route Protection}: Prevents unauthorized access to protected endpoints
\item \textbf{Error Handling}: Provides clear error messages for authentication failures
\end{itemize}

\paragraph{Authentication Functions}
\begin{itemize}
\item \textbf{verifyToken()}: Extracts and verifies JWT from cookies or Authorization headers
\item \textbf{checkAuth()}: Ensures user exists and attaches user object to request
\item \textbf{requireAuth()}: Middleware wrapper for protected routes
\end{itemize}

\paragraph{Authentication Process}
\begin{enumerate}
\item Extract JWT token from HTTP-only cookies or Authorization header
\item Verify token signature using JWT secret key
\item Decode token to extract user ID and other claims
\item Query database to find user by decoded token ID
\item Attach complete user object to request for downstream middleware
\item Call next middleware in chain or return authentication error
\end{enumerate}

\hypertarget{authentication-flow}{%
\subsubsection{6.1 Authentication Flow}\label{authentication-flow}}

\textbf{Registration Process}: 1. Frontend: User submits registration
form 2. Frontend: POST /api/auth/register with user data 3. Backend:
Validate input data 4. Backend: Hash password using bcrypt 5. Backend:
Create user in database 6. Backend: Generate JWT token 7. Backend: Set
HTTP-only cookie with token 8. Backend: Return user data (excluding
password) 9. Frontend: Update AuthContext with user data 10. Frontend:
Redirect to dashboard

\textbf{Login Process}: 1. Frontend: User submits login form 2.
Frontend: POST /api/auth/login with credentials 3. Backend: Find user by
email 4. Backend: Compare password with stored hash 5. Backend: Generate
JWT token if valid 6. Backend: Set HTTP-only cookie with token 7.
Backend: Return user data 8. Frontend: Update AuthContext 9. Frontend:
Redirect to intended page

\hypertarget{service-management-flow}{%
\subsubsection{6.2 Service Management
Flow}\label{service-management-flow}}

\textbf{Service Creation}: 1. Frontend: User fills ProvideService form
2. Frontend: Upload images via FormData 3. Frontend: POST /api/services
with service data 4. Backend: Validate user authentication 5. Backend:
Process uploaded images 6. Backend: Create service in database 7.
Backend: Return created service data 8. Frontend: Show success message
and redirect

\textbf{Service Search}: 1. Frontend: User applies filters on Search
page 2. Frontend: GET /api/services with query parameters 3. Backend:
Build MongoDB filter object 4. Backend: Execute paginated query with
population 5. Backend: Return services array with pagination info 6.
Frontend: Transform data for display 7. Frontend: Render ListingCard
components

\hypertarget{booking-and-payment-flow}{%
\subsubsection{6.3 Booking and Payment
Flow}\label{booking-and-payment-flow}}

\textbf{Complete Booking Process}: 1. Frontend: User clicks ``Book'' on
ListingCard 2. Frontend: Navigate to Payment page with property data 3.
Frontend: User completes payment form steps 4. Frontend: POST
/api/bookings to create booking 5. Backend: Validate service exists and
availability 6. Backend: Check for booking conflicts 7. Backend:
Calculate total amount and fees 8. Backend: Create booking with
`pending' status 9. Backend: Return booking data with ID 10. Frontend:
POST /api/payments with booking ID 11. Backend: Validate payment details
12. Backend: Create payment record 13. Backend: Update booking payment
status 14. Backend: Return payment confirmation 15. Frontend: Show
success message 16. Frontend: Navigate to dashboard

\hypertarget{wishlist-management}{%
\subsubsection{6.4 Wishlist Management}\label{wishlist-management}}

\textbf{Add to Wishlist}: 1. Frontend: User clicks ``Save'' on
ListingCard 2. Frontend: POST /api/wishlist/add with serviceId 3.
Backend: Validate authentication and service 4. Backend: Check if
already in wishlist 5. Backend: Add to user's wishlist array 6. Backend:
Return success response 7. Frontend: Update UI state

- Storage: Never store plain text passwords

\textbf{Indexes}: - user: For user's booking history - service: For
